# Backend handoff — نَسَق

النسخة الحالية متجر واجهات **Frontend-only**. بيانات الكتالوج تأتي من fixtures محلية تمر عبر Zod وmock transport؛ السلة والمفضلة محليتان، وendpoint الطلب ينشئ كيانًا تجريبيًا فقط.

## تشغيل المشروع

```bash
corepack pnpm install
corepack pnpm dev
```

## وضع البيانات

- `NEXT_PUBLIC_API_MODE=mock`: المسار الافتراضي، ويستخدم بيانات العرض المحلية.
- `NEXT_PUBLIC_API_MODE=http`: يختار fetch transport بعقود الكتالوج نفسها. يحتاج API حقيقيًا يلتزم بـ`STORE_API_CONTRACT.md`؛ ليس إعدادًا كافيًا لإطلاق الإنتاج.
- متصفح المستخدم يطلب من `NEXT_PUBLIC_API_BASE_PATH` النسبي، ولا يتصل بـ`localhost`.
- `NEXT_PUBLIC_ENABLE_REAL_CHECKOUT` يجب أن يبقى `false` في النسخة الحالية. لا توجد بوابة دفع أو تنزيل/تفعيل فعلي.

## ما يلزم قبل الإطلاق التجاري

توفير backend، توثيق مالك كل ثيم وحقوق عرضه، مراجعة بيانات الأسعار والتقييمات والتوافق، حماية ملفات التوزيع بروابط قصيرة العمر، وإضافة checkout حقيقي عبر مزود دفع مناسب بعد مراجعة المتطلبات القانونية والأمنية. تحقّق من وثائق وشروط سلة الرسمية الحالية قبل وصف أي منتج بأنه متوافق أو معتمد، ولا تخمّن API endpoints.
